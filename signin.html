Optim6 sign-in

Sign in outside the portal — for getting a token into Postman. Both methods land on the same POST …/unauth/platform/v6/sessions; they differ only in the proof they carry.

Sign in with a password

One call, no round trip: { method: "PASSWORD", username, password } and the response is the session. This is the v6 replacement for POST /v2/login and POST /unauth/platform/v5/login, which are frozen and deprecated.

Optional: land in a specific context

Both are optional and are validated as a pair (SW-2): an account granted admin in ISP B and engineer in ISP A asking for admin in ISP A is refused, even though each value appears in one of its grants. Left blank, the server elects the context. isp is a compartment id; * is GLOBAL.
